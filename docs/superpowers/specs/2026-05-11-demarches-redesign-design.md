# Démarches — Redesign & auto-création

**Date :** 2026-05-11  
**Scope :** `src/modules/admin/components/` · `app/layout.tsx` · `package.json`  
**Approche retenue :** Polish ciblé (Approche A)

---

## Contexte

La page « Mes démarches » (`/admin/demarches`) gère les démarches administratives liées aux statuts juridiques (intermittent, AE, SASU…). Avant ce redesign :

- Les démarches templates devaient être activées manuellement via un dialog sur la page Mes statuts.
- Il n'y avait pas de changement de statut inline sur la carte.
- Les dates limites n'avaient pas de code couleur lisible.
- Le formulaire d'ajout était lourd (tous les champs visibles d'emblée).

---

## Fonctionnalités à implémenter

### 1. Auto-création des démarches à la création d'un statut

**Déclencheur :** soumission du formulaire de **création** d'un nouveau statut dans `StatutEditPage` (pas d'édition).

**Comportement :**
1. Le statut est sauvegardé normalement via `setStatuses`.
2. Immédiatement après, on appelle `getTemplatesForStatusType(newStatus.type)` (lookup en mémoire, zéro réseau).
3. Si des templates existent pour ce type, `setProcedures` crée toutes les démarches avec :
   - `isAutoGenerated: true`
   - `status: "a_faire"`
   - `statutJuridiqueId: newStatus.id`
   - `templateKey: tpl.key`
   - `organisme: tpl.organisme`
   - `recurrence: tpl.recurrence`
   - `dateLimite`: aujourd'hui + `tpl.defaultDueInDays` (format ISO `YYYY-MM-DD`)
4. Un toast sonner affiche : `"N démarche(s) créée(s) pour ce statut"` (durée standard).
5. La redirection vers `/admin` continue normalement.

**Périmètre :** création uniquement. L'édition d'un statut existant ne crée pas de nouvelles démarches.

**Templates disponibles** (définis dans `src/modules/admin/data/procedure-templates.ts`) :

| Statut | Nb templates |
|--------|-------------|
| `auto_entrepreneur` | 2 (déclaration CA, CFE) |
| `intermittent` | 1 (actualisation France Travail) |
| `association_1901` | 1 (AG annuelle) |
| `sasu` | 1 (déclaration TVA) |
| `artiste_auteur` | 1 (déclaration URSSAF) |

### 2. Suppression du dialog de sélection de templates

Le dialog de sélection de templates dans `StatutsPage` devient inutile. Supprimer :

- Handler : `addTemplateProcedures`

Environ 80 lignes supprimées de `StatutsPage`.

### 3. Changement de statut inline sur les cartes démarches

**Pattern :** identique à Phono catalog (`CatalogPage.tsx` lignes 2002–2026).

Le badge d'avancement de chaque carte devient un `DropdownMenuTrigger` :

```tsx
<DropdownMenu>
  <DropdownMenuTrigger asChild>
    <button className={`${badgeClass} cursor-pointer hover:opacity-90 transition-opacity`}>
      {statusLabel(workflow)}
    </button>
  </DropdownMenuTrigger>
  <DropdownMenuContent align="start">
    {PROCEDURE_STATUS.map((s) => (
      <DropdownMenuItem key={s.value} onSelect={() => handleStatusChange(p.id, s.value)}>
        {s.label}
      </DropdownMenuItem>
    ))}
  </DropdownMenuContent>
</DropdownMenu>
```

**Logique de complétion avec récurrence :** extraire la logique actuelle de `saveEdit` (qui gère la création de l'occurrence suivante) dans une fonction `completeProcedure(p: AdminProcedure)`. Cette fonction est appelée depuis :
- Le dropdown inline quand on sélectionne « Terminé »
- Le formulaire d'édition (inchangé fonctionnellement)

### 4. Badge date limite color-codé

Remplace l'ancienne ligne de texte `"Date limite : JJ/MM/YYYY"` dans le corps de carte par un badge compact en haut à droite du header, style identique à `TaskCard.tsx` :

| État | Condition | Classes Tailwind |
|------|-----------|-----------------|
| En retard | `dateLimite < aujourd'hui` | `border-red-500/35 bg-red-500/15 text-red-300` |
| Bientôt | `dateLimite ≤ aujourd'hui + 7j` | `border-amber-500/35 bg-amber-500/15 text-amber-300` |
| Ok | `dateLimite > aujourd'hui + 7j` | `border-emerald-500/35 bg-emerald-500/15 text-emerald-300` |
| Pas de date | — | `border-[rgba(245,245,245,0.10)] text-[#F5F5F5]/40` (badge vide masqué) |

Format d'affichage : `dd MMM` via `new Intl.DateTimeFormat("fr-FR", { day: "2-digit", month: "short" })`.

La **bordure gauche** de la carte (ambre si en retard, jaune si ≤ 7j) est maintenue — elle opère à l'échelle de la carte, le badge à l'échelle de la ligne.

### 5. MetricChip « démarches » en warn si retard

Dans `StatutsPage`, le `MetricChip` `ClipboardList` passe `warn={hasOverdue}` où :

```ts
const overdueByStatusId = useMemo(() => {
  const today = new Date(); today.setHours(0,0,0,0);
  const set = new Set<string>();
  for (const p of procedures) {
    if ((p as {status?:string}).status === "termine") continue;
    const sid = (p as {statutJuridiqueId?:string}).statutJuridiqueId;
    if (!sid) continue;
    const dl = (p as {dateLimite?:string}).dateLimite;
    if (!dl) continue;
    const d = new Date(`${dl}T12:00:00`);
    if (!isNaN(d.getTime()) && d < today) set.add(sid);
  }
  return set;
}, [procedures]);
```

`warn={overdueByStatusId.has(s.id)}` — chip amber si au moins une démarche en retard pour ce statut.

### 6. Empty state amélioré par onglet

Quand un onglet de statut spécifique est sélectionné et que `scopedProcedures.length === 0`, le message est :

> *« Aucune démarche pour [nom du statut]. Les démarches types sont créées automatiquement à la création d'un statut. »*  
> + bouton « Ajouter une démarche »

## Contraintes & décisions

- **Pas de rétro-compatibilité :** les statuts existants ne reçoivent pas de démarches auto. C'est voulu.
- **Sonner :** bibliothèque toast légère (~3 kB), standard dans l'écosystème Next.js. Le `<Toaster />` est placé dans `app/layout.tsx` avec `theme="dark"` et `richColors` pour rester dans le design system dark-only.
- **Pas de dialog de confirmation :** la création auto est silencieuse sauf le toast. L'utilisateur peut supprimer les démarches créées s'il n'en veut pas.
- **`completeProcedure` extrait :** permet de ne pas dupliquer la logique de récurrence entre le dropdown inline et le formulaire. Reste dans `ProceduresPage.tsx` (pas de fichier séparé — la logique est simple).
